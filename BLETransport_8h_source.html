2// Selects the BLE transport adapter of the current platform and makes it
3// available under platform independent names, so that the same sketch or
4// program compiles everywhere:
5//
6// tinyblefs::BLEServerTransport server (peripheral) transport
7// tinyblefs::BLEClientTransport client (central) transport
8// tinyblefs::BLEScanResult element type returned by
9// BLEClientTransport::scan()
10//
11// Example:
12// #include "TinyBLEFS.h"
13// #include "TinyBLEFS/transports/BLETransport.h"
14//
15// BLEServerTransport transport;
16// transport.begin("TinyFS Sensor");
17//
18// auto found = BLEClientTransport::scan(5000, "TinyFS");
19// BLEClientTransport client;
20// client.connect(found[0]);
21//
22// Default selection:
23// ESP32 (Arduino or ESP-IDF) -> NimBLE.h (NimBLE-Arduino)
24// Raspberry Pi Pico W / 2 W -> PicoW.h (arduino-pico BLE)
25// any other Arduino board -> ArduinoBLE.h (ArduinoBLE)
26// desktop (Linux, ...) -> SimpleBLE.h (SimpleBLE)
27//
28// Override it by defining one of these before including this header:
29// TINYBLEFS_TRANSPORT_NIMBLE, TINYBLEFS_TRANSPORT_ARDUINOBLE,
30// TINYBLEFS_TRANSPORT_PICOW, TINYBLEFS_TRANSPORT_SIMPLEBLE
31// (e.g. to use ArduinoBLE on an ESP32).
32//
33// Only the common API is the same on all platforms: server begin(deviceName),
34// client scan(durationMs, namePrefix), connect(device) and disconnect(). The
35// adapter specific extras (setPacketSize, maxConnections, ...) are still there,
36// see docs/transports.md. TINYBLEFS_TRANSPORT_NAME is a string naming the
37// selected adapter.
